# 语义摄像头设计 — 从反无人机到场所语义判别平台

*2026-09 · 设计定稿 + M1 初期实现*

---

## 0. 一句话定位

> 把本仓库从"单一反无人机演示"扩展为**语义摄像头（Semantic Camera）**：同一套"门控 → 检测 → 跟踪 → 判别 → 告警"边缘流水线，按**场所加载模式包**；JEPA 判别**全自动闭环**——设计红线：判别流水线的任何环节不得依赖人工判定。

## 1. 为什么扩展

反无人机的方向太窄：模型、类别、告警规则全部写死在代码里，只有一个场景。但这条管线里已经验证的资产全部是通用的：

| 已验证资产 | 通用性 |
|---|---|
| 帧差运动门控 + 触发式检测（400ms/巡检 5s） | 与目标类别无关 |
| IoU+恒速跟踪 + 多帧确认 + 分级老化 | 与目标类别无关 |
| JEPA 判别器（DINOv2 特征 + 线性探针，离线 98.15%） | 换探针头即可判别任何二类语义 |
| 全量遥测（IndexedDB + CSV/JSON + 双端原生桥） | 与目标类别无关 |

价值位：传统 NVR 标准件（运动检测/人形检测）误报泛滥，值班员被告警疲劳淹没。**语义判别层的价值 = 把误报判掉 + 按场所语义决定什么值得告警**。这层是 NVR 标准件之上的增量，不与感知层竞争（与 vus/rvs 的定位表述一致）。

## 2. 与 vus 的关系（架构基座）

依旧基于 Video Understanding Skill（vus）的快慢双系统与成本上限工程。速度栈映射：

```
T0   帧差反射        MotionGate，逐帧，毫秒级，永不缺席
T1   触发式检测      YOLOv8s，有运动 400ms / 无运动巡检 5s
T1.5 边缘判别        DINOv2 探针，只对确认目标，30s 节流，懒加载
T2   慢脑仲裁        vus VLM，只接灰区案件，预算硬上限（M2 落地）
```

复用的 vus 机制：**触发式慎思**（只有值得想的才升级）、**成本上限**（仲裁预算/小时）、**单飞合并**（按轨迹去重，一个案件只裁一次）。语义摄像头的边缘核心 = vus 四级速度栈在浏览器端的首两级 + T1.5 判别器；T2 通过桥接 vus 慢脑完成。

## 3. 场所模式包（核心抽象）

**模式包 = 纯数据**：换场所不改流水线代码，只换检测模型 / 判别头 / 告警规则。schema（`web/core.js` 中 `MODE_PACKS`）：

```js
{
  id: 'airfield', name: '净空防黑飞',
  detector: './yolov8s-drone.onnx',          // 场所检测模型
  discriminators: {
    main: {                                   // 主判别任务：二类探针
      classes: ['bird', 'drone'],             // [负类, 正类]，探针输出 P(正类)
      probe: './jepa_probe_init.json',        // 初始化探针头
      alertConf: 0.80,                        // 胜出侧置信度闸门
    },
  },
  alertCls: 'drone',                          // 本场所的告警类别
  arb: { budgetPerHour: 20, ttlMs: 15000 },   // 仲裁预算 + 轨迹去重窗
  selfTrain: { minConf: 0.90, marginRatio: 0.80, cooldownMs: 60000, lr: 0.05 },
}
```

### 首波场所目录（按里程碑陆续落地）

| 模式包 | 判别任务 | JEPA 的价值（误报杀手） | 状态 |
|---|---|---|---|
| **airfield 净空防黑飞** | 鸟 / 机 | 鸟群与飘动物不告警，黑飞必报；灰区不虚报 | ✅ M1 已落地 |
| **depot 油库烟火** | 烟 / 雾·晚霞·水汽 | 烟火误报是安防行业第一痛点，正是细粒度判别的主场 | M3 |
| **site 工地合规** | 戴盔 / 未盔 | 人形检测无法区分，事件规则按区域+判别结果组合 | M3 |
| **campus 校园周界** | 人 / 影子·海报·树枝 | 夜间低照度误报抑制 | M3 |
| **farm 养殖驱避** | 鸟 / 兽 / 人 | 分类决定驱避策略，误判即误驱 | M4 |

扩展一个新场所 = 新增一个模式包数据 + 对应判别头文件 + （可选）新检测模型，流水线零改动。

## 4. JEPA 全自动判别（去人工化）

**设计红线**：如果判别需要人来看、人来定，这个功能就不成立。原设计里"用户点 🕊/🛸 反馈 → 在线学习"的人工回路整体废除，替换为三层自动机制：

### 4.1 四态语义裁决（JepaPolicy，全自动）

探针输出 P(正类)，裁决器给出四种语义态，全部机器决策：

| 态 | 条件 | 行为 |
|---|---|---|
| `alert` | 目标侧且置信 ≥ alertConf | 告警（HUD 红字 + 遥测 conf 事件） |
| `escalate` | 目标侧但置信 < alertConf | **弃权不虚报**，入慢脑仲裁队列（预算内） |
| `clear` | 非目标侧且置信 ≥ alertConf | 判明非目标，抑制告警 |
| `suppress` | 非目标侧低置信 | 静默 |

关键语义：**灰区宁可弃权不可虚报**——`escalate` 的目标不触发告警（挂牌"待仲裁"），这正是人工按钮想解决但解决不好的问题（误报打扰 vs 漏报风险）的机器化答案。判别结果未出之前，检测器权威（防漏报）。

### 4.2 边缘自训练（替代人工反馈的自动进化）

在冻结的 DINOv2 特征上，当**双信号一致且足够确信**时自动更新探针头：

1. logreg 头置信度 ≥ 0.90；
2. 原型距离一致性：胜出侧原型距离 / 落败侧 ≤ 0.80（两个独立信号互相验证，防止错误自我强化）；
3. 冷却 60s/轨迹，质心滑动平均 + logreg 单步 SGD（梯度下降），持久化 localStorage。

更新路径与原人工反馈完全同源（`probeLearn`），只是**标签来源从人变成了机器一致性**。

### 4.3 慢脑仲裁回灌（M2）与离线再训练（M4）

- **M2 vus 桥**：本地 WS 服务把灰区 crop 送 vus 慢脑 VLM 仲裁，结论作为伪标签经同一 `probeLearn` 路径回灌探针。仲裁队列（`ArbitrationQueue`）本轮已落地：预算 20 件/小时硬上限 + 按轨迹 TTL 去重，桥未接入时事件落遥测（CSV/JSON 可导出），接入后即可消费。
- **M4 离线再训练**：仲裁日志累积 → `scripts/train_probe.py` 离线重训探针头 → 任务级闸门校验（复用量化工具"检出数不降 10% 且 IoU≥0.8"的静默失效防线）→ 产出新 `jepa_probe_*.json` 随模式包发布。

### 废案与保留

- **废除**：🕊/🛸 人工判定按钮（判定的职责已全部机器化）。
- **保留**："重置学习"按钮——恢复初始化权重，属运维操作，不是判定环节。

## 6. 验证口径

- 单测新增：四态裁决边界（0.80/0.50 阈值两侧）、仲裁队列去重/预算/小时窗滚动、自训练门控（双信号一致才放行）、probeLearn 数值方向性、探针格式归一化兼容旧字段；既有 21 例不回归。
- CI 三副本一致性照常强制。
- 探针离线精度 98.15%（162 样本）不变——本轮只改**判定语义与标签来源**，不动初始化权重。
